# CLEANUP_STRATEGY_v1.0.md
**Version:** v1.0
**Applies To:** Nexus Core MVP1
**Planning Task:** ING-PLAN-006 - Cleanup and Reset Strategy

---

## 1. Purpose

This document defines the **authoritative cleanup and reset strategy** for Nexus Core MVP1.

Its purpose is to:
- Enable safe, repeatable ingestion and validation tests
- Prevent cross-test contamination
- Ensure deterministic test outcomes
- Preserve auditability while removing test effects

Cleanup is a **mandatory phase** after every ingestion or validation test run.

---

## 2. Cleanup Principles (Non-Negotiable)

- Cleanup MUST be explicit and operator-invoked
- Cleanup MUST be deterministic and repeatable
- Cleanup MUST NOT silently delete data
- Cleanup MUST preserve audit history
- Cleanup MUST restore a known clean baseline
- Cleanup MUST be observable (logs and confirmation)

---

## 3. Definition of Test Data

For MVP1, **test data** is defined as:

- Sources manually placed in `/transfer_station/sources/` for testing
- All artifacts derived from those sources
- All database rows derived from those sources
- Validation reports produced by test runs

Test data is scoped by **doc_id** and **sha256**, not filenames.

---

## 4. What MUST Be Removed or Reset

Cleanup MUST address the following categories.

---

### 4.1 Source Files

**Location:**
```
/transfer_station/sources/
```

Cleanup MUST:
- Remove test source files placed by the operator
- NOT remove unrelated files

Operator confirmation is REQUIRED.

---

### 4.2 Ingestion Artifacts

**Locations:**
```
/transfer_station/artifacts/manifests/
/transfer_station/artifacts/chunks/
/transfer_station/artifacts/assets/
```

Cleanup MUST:
- Remove artifact directories for test `doc_id`s
- Preserve directory structure

Artifacts for non-test sources MUST NOT be touched.

---

### 4.3 Validation Reports

**Location:**
```
/transfer_station/artifacts/reports/
```

Cleanup MUST:
- Remove validation reports generated by test runs (per test `doc_id`)
- Leave unrelated reports intact

---

### 4.4 Database Records

Cleanup MUST:
- Soft-deactivate all test sources
- Remove or reset DB rows created during test runs, including:
  - governance records
  - chunk records
  - embeddings
  - index entries

Cleanup MUST restore the database to a **known clean baseline**.

Schema resets are FORBIDDEN without explicit confirmation.

---

## 5. What MUST Remain

Cleanup MUST NOT remove:
- Database schema and migrations
- Non-test sources and artifacts
- Configuration files
- Logs unrelated to the test run

Audit integrity MUST be preserved.

---

## 6. Cleanup Verification Steps

After cleanup, the system MUST verify:
- `/transfer_station/sources/` contains no test files
- `/transfer_station/artifacts/manifests/` contains no test artifacts
- `/transfer_station/artifacts/chunks/` contains no test artifacts
- `/transfer_station/artifacts/assets/` contains no test artifacts
- `/transfer_station/artifacts/reports/` contains no test reports
- No active or ingested test sources remain in governance
- Retrieval queries return no test-derived results

Verification results MUST be logged.

Automated verification:
- A cleanup verification script MUST run these checks
- Script must return pass/fail exit codes

---

## 7. Cleanup Execution Rules

- Cleanup MUST be run from a controlled script (e.g., PowerShell)
- Cleanup MUST print each step being performed
- Cleanup MUST fail fast on errors
- Cleanup MUST return explicit exit codes

Hidden automation is forbidden.

---

## 8. Failure Handling

If cleanup fails:
- The failure MUST be logged
- The environment MUST be considered contaminated
- Further tests MUST NOT proceed

Manual intervention is required before continuing.

No automatic rollback or retry is permitted for cleanup failures.

If cleanup partially completes:
- Record which steps succeeded and which failed
- Do not attempt compensating deletions automatically
- Operator must re-run cleanup after resolving the failure cause
  (e.g., file lock, DB connection, permission issue)

## 11. Acceptance Statement

The cleanup strategy for Nexus Core MVP1 is accepted when:
- Test runs can be repeated without contamination
- Cleanup restores a known clean state
- No test artifacts affect subsequent ingestion or queries

This document defines the **authoritative cleanup contract** for MVP1.

---

## 12. Safety Rationale (Git Memory Compliance)

### Why Cleanup is Mandatory

Cleanup is mandatory for MVP1 because:

1. **Test Repeatability**: Tests must produce identical results across runs; leftover data causes false passes/fails
2. **Container-Only Testing**: All tests run inside Docker per NFR-007; contaminated state invalidates subsequent tests
3. **Determinism Verification**: Ingestion must be reproducible; orphaned data prevents verification
4. **Safety Validation**: Production safety depends on test reliability; contaminated tests cannot prove correctness
5. **Governance Integrity**: State machine must be testable from known states; residual data violates preconditions
6. **No Synthetic Data**: Per NFR-008, all test data is real sources that must be cleaned to prevent confusion

### Mandatory Nature

Per TEST_PLAN_v1.0.md Section 5.2:
> "Cleanup MUST restore the environment to a known clean state."

This is not optional. Without cleanup:
- Tests become non-deterministic
- Validation results become unreliable
- Production readiness cannot be certified
